# Сценарии разговоров для sim_conversation

По файлу на пациента: реплики менеджера, которые ведут разговор так, как
он должен идти при грамотной работе. Абзац — одна реплика.

**Сценарий пишется под ключевую деталь пациента**, иначе прогон проверяет
не характер, а вежливость. Торопливой маме — цифры сразу, паранойику —
документы и предложение проверить, подрядчику — смета, робкой — тихий
темп и поддержка, когда муж не берёт трубку.

Запуск изнутри backend-контейнера на DE (потолок первого токена настроен
под тамошний сетевой путь):

    python scripts/sim_conversation.py <промпт.txt> scripts/dialogues/<имя>.txt

Промпт берётся из базы — это собранная строка `PatientCase.prompt`, а не
файл в репозитории: случай собирается под клинику.

## Что смотреть в выводе

* **ИСХОД** — `paid`, `refused` или `not_asked`. Отказ сам по себе не дефект:
  если сценарий не снял обязательное условие, отказ верен. Смотреть надо
  строку «разбор для нас» — она перечисляет, что снято, а что нет;
* **сбоев и пустых ответов** должно быть ноль. Ненулевые — это стенд или
  провайдер, а не поведение роли;
* **узнаётся ли характер**. Это читается глазами и никаким счётчиком
  не заменяется: за день 31.07 три моих регулярки подряд дали неверный
  вердикт по русскому тексту.
