# Шпаргалка по проекту

Голосовой ИИ-тренажёр по продажам: менеджер разговаривает голосом с ИИ-клиентом
«Тамарой Михайловной», после разговора остаётся расшифровка. Подробности —
в [README.md](README.md), деплой — в [DEPLOY.md](DEPLOY.md).

## Архитектура в двух абзацах

**`frontend/`** (Next.js 14, App Router) — интерфейс, авторизация и вся работа
с БД через Prisma. Здесь же REST API (`app/api/**`). Единственная роль в
голосовом сценарии — выдать одноразовый ws-токен; сам разговор идёт из браузера
по WebSocket напрямую в backend.

**`backend/`** (FastAPI) — голосовой пайплайн STT → LLM → TTS на одном
WebSocket-соединении. Вынесен в отдельный сервис и на зарубежный сервер, потому
что ElevenLabs не отвечает на российские IP. Пишет сообщения в ту же PostgreSQL.

## Команды

```powershell
docker compose up -d                  # PostgreSQL (5433) + Redis (6379)

cd frontend
npm run dev                           # http://localhost:3000
npx tsc --noEmit                      # типы
npm run lint                          # ESLint
npx prisma migrate deploy             # применить миграции
npm run prisma:migrate                # создать миграцию
npm run seed:content                  # советы дня и мотивации
npm run seed:patients                 # пациенты и их промпты
npm run seed:training                 # типы тренировки и их промпты
npm run seed:achievements             # достижения
npm run seed:team                     # демо-менеджеры для статистики РОПа
npm run seed:demo                     # демо-аккаунт и задания (после двух сидов выше)
npm run create-user                   # интерактивно (ввод — за пользователем)

cd backend
.\.venv\Scripts\Activate.ps1
uvicorn main:app --host 127.0.0.1 --port 8000
pytest tests/
```

### Грабли локальной разработки

**Не запускать `npm run build` при работающем `npm run dev`.** Обе команды пишут
в одну папку `.next`: продакшен-сборка перезаписывает её, и dev-сервер теряет
свои чанки. Проявляется как `Cannot find module './276.js'`, 404 на всех
`/_next/static/*` или страница без стилей. Для проверки кода без остановки
сервера есть `npx tsc --noEmit` — он в `.next` не пишет.

**Лечится удалением `.next`** (папка целиком генерируемая, терять нечего):

```powershell
Remove-Item -Recurse -Force frontend\.next
```

Тот же рецепт помогает после переключения веток, если сборка «залипла».

**Prisma на Windows:** `prisma generate` падает с `EPERM`, если запущен
dev-сервер — он держит DLL движка. Остановить `npm run dev`, сгенерировать,
запустить снова.

**После миграции нужен `prisma generate`**, даже если миграция уже применилась
к базе. Клиент помнит прежнюю схему, и роут падает с `Unknown argument` на
новом поле — выглядит как ошибка кода, хотя код верный.

**Backend локально адресуется как `127.0.0.1`, не `localhost`.** Node резолвит
`localhost` в IPv6 `::1`, а uvicorn слушает IPv4 — вызов из роутов Next
упирается в `ECONNREFUSED`. Браузеру это безразлично, поэтому промах виден
только на серверных вызовах: голосовой разговор идёт, а генерация случаев
молча не работает.

### Проверка вёрстки в браузере

Если снимаешь стили через `getComputedStyle` в фоновой/скрытой вкладке, помни:
без отрисовки кадров **CSS-переходы не продвигаются**, и замер возвращает
стартовое значение. Из-за этого легко решить, что стиль «не применился», хотя
класс на месте. Перед замером отключай анимации:

```js
document.head.insertAdjacentHTML('beforeend', '<style>*{transition:none !important}</style>');
```

В скрытой вкладке молчит не только анимация. **Картинки с `loading="lazy"`
там вообще не запрашиваются**: браузер считает, что они не попали в область
просмотра, и `img.complete` у всех остаётся `false`. Выглядит как поломка —
двадцать один `<img>` в разметке, ноль запросов в сети, — хотя сам файл
отдаётся за двадцать миллисекунд. Прежде чем чинить, проверь
`document.visibilityState` и сними ленивость:

```js
document.querySelectorAll('img[loading="lazy"]').forEach(i => i.loading = 'eager');
```

Ещё одна ловушка: `border-[1.5px]` Tailwind **не генерирует** — значение
неоднозначно (ширина или цвет). Нужен префикс: `border-[length:1.5px]`.

**React не перерисовывается в том же синхронном блоке**, где произошёл клик.
Прочитав DOM сразу после `click()`, получишь состояние до перерисовки и решишь,
что обработчик не сработал. Между действием и замером нужна пауза.

### Воспроизведение речи: три грабли MSE

Оплачены тремя заходами на «Тамара затупила», и первые два лечили следствия.

1. **О воспроизведении нельзя судить по `buffered`** — только по продвижению
   позиции. Из-за этого залипал индикатор «Слушаю вас».
2. **Застрявший элемент не на паузе** и может иметь `readyState` 4.
   `!audio.paused` как признак «играет» — неверен.
3. **Chromium не возобновляет воспроизведение сам**, когда звук дописали после
   тишины: позиция стоит, данные впереди, ничего не происходит. Это не сбой,
   а поведение по умолчанию. Лечится микро-перемоткой в `updateend`, сразу
   после дописывания, — не по срабатыванию сторожа: сторож честен, но ждёт
   две секунды, и это те самые «затупила».

Симптом обманчив вдвойне: жалуется пользователь на ИИ, а виноват браузер.
Здоровое состояние в логах (строки `ПЛЕЕР`) — `heartbeat` с растущей позицией
плюс `nudge (append)` в начале каждой реплики. Тревога — `stall`, `rebuild`,
`audio-error`, `play-rejected`.

## Дизайн

Макеты живут в **Claude Design**, проект `ea4fb9e2-0fa6-411f-a86f-60a51be5b26c`
(«Дизайн №2 (ии-тренажер)»). Читать через MCP-инструмент `DesignSync`
(`method: get_file`, файлы вида `Главная.dc.html`). Выбрано направление
**1A «Спокойная клиника»**, дизайн-язык — в `Дизайн-язык.dc.html`.

Внутри `.dc.html` бывает не только вёрстка, но и логика компонента (например,
на главной — ротация «Совет дня»/«Мотивация» и выбор текста по индексу дня).
Её стоит вычитывать, а не додумывать поведение.

**Правила вёрстки:**

- только **светлый десктоп** — мобильную версию и тёмную тему делаем позже,
  разом для всех экранов;
- цвета берём из семантических токенов `frontend/tailwind.config.ts`
  (`brand`, `ink`, `surface`, `line`, `danger`, `good`, `warn`), а не подбираем
  hex в разметке;
- макеты рисуются под конкретную ширину — проверять, что задумано на широких
  экранах, и не растягивать блоки долями там, где размер диктуется содержимым.

## Соглашения по коду

- Комментарии и текст интерфейса — **на русском**. Комментарии объясняют
  «почему», а не пересказывают код.
- Роуты API: `runtime = "nodejs"`, авторизация через `getAuthUser` из
  `@/lib/auth`, доступ к БД через `prisma` из `@/lib/db`.
- Изменяющие роуты проверяют владельца прямо в условии запроса
  (`updateMany({ where: { id, userId } })`), а не отдельным запросом.
- Тестами покрываем чистую логику (например, классификатор поддакиваний).
### Сборка случая пациента: порядок вопросов и есть механизм

Личность пациента написана вручную и одна на все клиники. Случай — с чем
человек пришёл именно сюда — собирается в три вызова, и **порядок здесь
важнее всего остального**.

1. `clinical_picture.generate_pictures` ставит диагноз, **не зная ни услуг,
   ни цен**. Отдаёт 3–5 картин, каждая с четырьмя измерениями: когда
   состояние начинается, обычное ли оно для этого возраста, какая стадия,
   при каких условиях человек это замечает.
2. `clinical_picture.match_services` подбирает услугу **под** диагноз
   отдельным узким вопросом. Диагностический приём лечением не считается.
3. `case_generator.write_case` пишет прозу, получив картину как данность.
4. `case_review.review` перечитывает готовое другой моделью и говорит,
   **чей** брак — картины или прозы. От этого зависит, что пересобирать.

Раньше всё делал один вызов, знавший про продаваемую услугу, — и модель
брала услугу, а болезнь подгоняла под неё. Два врача забраковали сборку
целиком: миопия, впервые возникшая в 48 лет, катаракта с жалобой не на ту
функцию. В графе «объективно» стояло «требуется лазерная коррекция зрения»,
то есть вывод о продаже вместо находки осмотра.

**Чиним измерения, а не факты.** Все семь замечаний двух врачей разошлись
по четырём измерениям выше, и ни одно не офтальмологическое: окно начала,
частота в возрасте, стадия и её симптомы, условие проявления есть у любой
отрасли. Список болезней глаза помог бы двум отраслям и провалился бы
на третьей, которую никто не вычитывал.

**Модели выбраны замером, а не по прайсу.** Клинический шаг на
`claude-sonnet-5` дешевле, чем на `gemini-3.5-flash`, хотя дороже
по списку: размышления тратит в тринадцать раз меньше. Критик на дешёвой
`gpt-5.6-luna` ловит 7 браков из 8, а `gpt-4o-mini` — только 3.
Скрипты замеров: `scripts/measure_anamnesis.py`, `scripts/measure_critic.py`.

- **Поведение промптов тестами не проверяется** — для него есть `backend/qa/`:
  прогон пациентов по типам, метрики и чтение расшифровок отдельной моделью.
  Правил промпт — прогони, иначе поломку найдёт пользователь. Оба самых
  дорогих дефекта июля-августа нашлись чтением при отличных оценках.
- Вживую остаётся только то, что слышно: голос, паузы, перебивания.

## Про продакшен

`main` уезжает в прод автоматически: push → сборка образов → деплой на оба
сервера с рестартом. Мерж = выкатка, рестарт backend обрывает активные
голосовые сессии. При старте контейнера сами накатываются миграции,
пересобираются промпты пациентов и заливаются советы с мотивациями —
то есть всё, чей источник правды лежит в репозитории. Вручную наливаются
только пользователи и демо-данные.

Разбор разговора ставится автоматически: фоновый оценщик считает этапы по ходу
разговора, итоговый — записывает исход сделки и выводы после завершения сессии
(`backend/services/scoring.py`, механизм целиком — в [DEAL-OUTCOME.md](DEAL-OUTCOME.md)).
В демо-данных оценки руками не задаются: закрытие, исход и общая оценка
выводятся из четырёх этапов той же формулой (`frontend/scripts/deal-result.ts`).

**Пароли демо-аккаунтов сиды ставят только при создании.** Повторный запуск
их не меняет — иначе перезалив данных ломал бы вход. Сменить намеренно:
`DEMO_PASSWORD` / `HEAD_PASSWORD` / `TEAM_PASSWORD`.
