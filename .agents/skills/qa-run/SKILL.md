# Прогон проверки промптов

Прогон платный. Ориентир прежних замеров: **3 цента за клетку**, полная
матрица (147 клеток) — около **$4.40** и минут двадцать при параллельности 5.
Перед запуском уточнить объём прогона и актуальную оценку расходов.

Запускать **только по прямой просьбе пользователя**. Наличие локального
хука `guard-spend.js` не гарантирует, что текущая среда его выполняет.
Не полагаться на хук как на разрешение или обязательный запрос подтверждения.

## Перед запуском

1. Дождаться, пока деплой доедет: пересоздание контейнера **обрывает прогон**.
   Сверять время сборки образа со временем старта контейнера, а не смотреть
   на статус воркфлоу.
2. Убедиться, что в выкаченном образе лежит нужный код, — grep по строке
   из свежей правки. Если строку не нашли в образе, значит гоняем старое.
3. Прогонов сейчас быть не должно: см. «Как проверить, что ничего не идёт».

## Запуск

Два круга, чтобы не платить за чтение всех клеток подряд:

```bash
# 1. Вся матрица, только арифметика — дёшево
docker exec -d -e QA_GIT_SHA=<sha> ai-trainer-backend-1 \
  sh -c 'cd /app && python -m qa.run --all --no-reader > /tmp/qa.log 2>&1'

# 2. Модель дочитывает только помеченные клетки
docker exec -d ai-trainer-backend-1 \
  sh -c 'cd /app && python -m qa.run --reread <прогон> > /tmp/qa-read.log 2>&1'
```

Промпты берутся из базы сами — выгружать файлы не нужно. А вот **сценарии
разговоров живут в образе**, и после пересоздания контейнера они на месте,
тогда как всё, что копировалось руками, пропадает.

## Наблюдение

```bash
docker exec ai-trainer-backend-1 sh -c 'cat qa-runs/*/progress.json; tail -3 /tmp/qa.log'
```

## Остановка — и как убедиться, что она случилась

**В образе нет `ps`, `pkill`, `pgrep`, а `kill` — встроенная в оболочку,
не программа.** Поэтому `pkill` возвращает успех, ничего не сделав, а
`xargs kill` падает с «No such file or directory». 04.08 из-за этого прогон
работал ещё двенадцать минут после моего «остановлено» и потратил лишний
доллар.

Перезапуск контейнера завершает процессы внутри него, но также обрывает
боевые разговоры. Использовать его только при согласованном перезапуске:

```bash
docker restart ai-trainer-backend-1
```

Бэкенд недоступен около десяти секунд; активные голосовые сессии оборвутся.

**Останов нужно проверить.** Убедиться, что процесс прогона завершился:
проверить процессы через `/proc/[0-9]*/cmdline`, отличая сам прогон от
проверяющей команды. После согласованного перезапуска проверить успешный
запуск контейнера и отсутствие нового прогона. Дополнительно сравнить число
файлов результатов дважды с паузой:

```bash
docker exec ai-trainer-backend-1 sh -c 'ls qa-runs/*/results/*.json | wc -l'
# подождать 40 секунд
docker exec ai-trainer-backend-1 sh -c 'ls qa-runs/*/results/*.json | wc -l'
```

Неизменное число файлов само по себе **не доказывает остановку**: процесс
может ждать ответ модели или зависнуть. Если завершение процесса не проверено,
не сообщать пользователю, что прогон остановлен.

Не считать процессы через `grep /proc/*/cmdline | wc -l`: там всегда минимум
два совпадения — сам grep и оболочка.

## Как проверить, что ничего не идёт

Проверить отсутствие процесса прогона через `/proc` и дополнительно сравнить
число файлов с паузой. Отсутствие новых файлов не заменяет проверку процесса.

## После прогона

Сводка — `qa-runs/<прогон>/summary.md` внутри контейнера. Забирать через
`docker exec … cat`, наружу она сама не попадает.

Прерванный прогон доделывается `--resume <прогон>`: готовые клетки
пропускаются, ничего не теряется.

**Но только пока жив контейнер.** `qa-runs/` лежит в файловой системе
контейнера, а не в томе. `docker restart` её сохраняет, а **любой деплой
пересоздаёт контейнер и стирает все результаты** — `--resume` тогда нечего
подхватывать. 04.08 так пропали 37 оплаченных клеток.

Поэтому: забирать `summary.md` и `results/` наружу **сразу после прогона**,
не откладывая, и не начинать прогон, если на подходе мерж в `main`.
